# Задача на тестирование: Butterfly PHP

**Передано:** разработчиком (PHP 8.5.12 + MySQL) → QA
**Дата:** 24.10.2026
**Объект:** `butterfly-php` — PHP-версия приложения «Butterfly — учебный планер»
**Версия:** 1.0.0-php
**Стенд для теста:** локальный (PHP 8.5.12, MySQL 8.4.0), доступ — `http://127.0.0.1:8093`
**Учётка:** `test` / `test` (демо; см. `scripts/seed-demo.php`)

---

## 1. Что передано

- PHP-backend: `app/` (API, сессии, валидация, лимиты, БД).
- Веб-корень: `public/` (фронтенд без изменений + `api.php` + `.htaccess`).
- Схема MySQL: `migrations/001_init.sql`.
- Скрипты: `scripts/migrate.php`, `scripts/seed-demo.php` (локально), `scripts/cleanup-qa.php` (локально).
- Тесты: `tests/api_test.php` (80 проверок), `tests/ui-smoke.mjs`, `tests/final-check.mjs`.
- Документация: `README.md`, результаты прошлого прогона в `audit/`.

## 2. Как поднять стенд

```powershell
# PHP 8.5.12+ и MySQL 8.0+ должны быть установлены
copy .env.example .env          # DB_*, APP_URL, COOKIE_SECURE=0
php scripts/migrate.php
php scripts/seed-demo.php
php -S 127.0.0.1:8093 -t public router.php
```

Проверка, что сервер отвечает: `GET /api/health` → `{"ok":true,...}`.

После тестов:

```powershell
php scripts/cleanup-qa.php      # удалить временных пользователей
php scripts/seed-demo.php       # вернуть демо-состояние test/test
```

## 3. Обязательные проверки

### 3.1 Автотесты (обязательно, приложить вывод)

- [ ] `php tests/api_test.php` — **80 проверок, 0 провалов**.
- [ ] `node tests/ui-smoke.mjs` (BASE_URL) — вход, сохранение после reload, настройки, экспорт, мобильный вид, service worker.
- [ ] `node tests/final-check.mjs` — чистая проверка без изменений; скриншоты в `audit/`.
- [ ] В логе PHP (`php-server.log`) нет `Fatal error`, `Warning`, `Notice`, `Uncaught`.

### 3.2 Аккаунты и сессии

- [ ] Регистрация **закрыта**: на `/login.html` нет вкладки регистрации; `POST /api/register` → **403 `REGISTRATION_DISABLED`**.
- [ ] Вход: аккаунт, созданный администратором (`scripts/add-user.php`); неверный пароль — 401; после 5 неудач — 429 с `Retry-After`.
- [ ] Cookie: `HttpOnly`, `SameSite=Lax`; при `COOKIE_SECURE=1` — `Secure`.
- [ ] «Запомнить меня навсегда»: cookie с `Max-Age` около 10 лет; при выходе сессия и cookie очищаются; на чужом устройстве включать не рекомендуется.
- [ ] Выход стирает сессию; `/api/me` после выхода — 401.
- [ ] На главной странице видны имя, логин (`@login`) и кнопка «Выйти»; выход возвращает на страницу входа.
- [ ] Просроченная сессия (удалить строку из `sessions` или выставить `expires_at` в прошлое) → 401.
- [ ] Смена пароля: старый перестаёт работать, новый работает; другие сессии завершены.
- [ ] Удаление аккаунта: без пароля/с неверным паролем — 400; с верным — данные и сессии удалены.

### 3.3 Персональная база

- [ ] Два пользователя A и B: A не видит данные B (UI и API), экспорты различаются.
- [ ] `PUT /api/state` с актуальной ревизией — 200; со старой — 409 `STATE_CONFLICT` с актуальной `rev`.
- [ ] `v: 3` в данных — 400; слишком большое состояние (>512 КБ) — 413.
- [ ] Санитайзер: длинные строки обрезаются, невалидный цвет заменяется `#8a7a9c`, даты/время проверяются.
- [ ] Сохранение после перезагрузки страницы; правка при закрытии вкладки не теряется.
- [ ] Экспорт: `Content-Disposition: attachment`, JSON `app/schema_version/account/data`, без паролей/сессий; в выгрузке нет чужих данных.

### 3.4 Безопасность

- [ ] Заголовки: CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- [ ] `X-Powered-By` отсутствует.
- [ ] `POST/PUT` с чужим `Origin` — 403 (CSRF).
- [ ] Прямой `/api.php` — 404; `.env`, `.user.ini`, `.htaccess` недоступны из веба.
- [ ] Нет внешних запросов от приложения (шрифты/скрипты локальные).
- [ ] Пароли в БД — Argon2id (`$argon2id$...`).
- [ ] Лимиты хранятся в MySQL и не сбрасываются при перезапуске PHP.
- [ ] Логин/пароль не попадают в логи.

### 3.5 Интерфейс и PWA

- [ ] Вход/ошибки — на русском, понятные; показ пароля работает; вкладки регистрации нет.
- [ ] Все 7 разделов: «Сегодня», «Контрольные», «Календарь», «Тренировки», «Учёба», «Итоги дня», «Отладка» — открываются, данные сохраняются.
- [ ] Раздел «Отладка»: одно окно свободного текста, кнопка «Отправить», правила безопасности; POST `/api/debug` сохраняет запрос, GET `/api/debug` возвращает только свои запросы; лимит длины и частоты.
- [ ] Настройки: смена пароля, выгрузка JSON, установка PWA, выход, удаление аккаунта.
- [ ] Пустое состояние: «Добавить примеры» и «Начать с чистого листа».
- [ ] Адаптив: 320/390/768/1024/1400 px — без горизонтального скролла, нижняя панель не перекрывает контент.
- [ ] PWA на iPhone (вручную, HTTPS-стенд): Safari → «Поделиться» → «На экран „Домой“» → запуск без адресной строки.
- [ ] Офлайн (вручную): открыть, отключить сеть, перезагрузить — оболочка из кэша, баннер «Нет сети».
- [ ] Консоль браузера: 0 ошибок (кроме ожидаемого 401-пробы `/api/me` на странице входа — допустимо).

### 3.6 Развёртывание (проверить на реальном хостинге)

- [ ] PHP в панели — **8.5.12+** (проверить `phpinfo()`).
- [ ] MySQL — 8.0+ (поддержка JSON), кодировка `utf8mb4`.
- [ ] `.htaccess` работает: HTTPS-редирект, `/api/*` → `api.php`, CSP, MIME `.webmanifest`/`.woff2`.
- [ ] `COOKIE_SECURE=1`, `APP_URL=https://...`; cookie `Secure` в браузере.
- [ ] Демо `test/test` отсутствует на проде; новые аккаунты создаёт администратор (`scripts/add-user.php`), регистрация закрыта.
- [ ] Бэкап MySQL по cron создаётся; восстановление из дампа проверено.
- [ ] `expose_php=Off` (панель), `display_errors=Off`.

## 4. Критерии приёмки

- 80/80 API-проверок, 0 провалов.
- UI-сценарии проходят, скриншоты обновлены.
- 0 дефектов уровня critical/high; medium/low — исправлены или явно приняты.
- 0 предупреждений/фатальных ошибок PHP в логе.
- Проверки на хостинге (пункт 3.6) закрыты.
- QA-отчёт приложен, дефекты при наличии — с шагами воспроизведения и severity.

## 5. Вне объёма этой задачи

Google-синхронизация, восстановление пароля по почте, нативные приложения, push-уведомления, нагрузочное тестирование сверх smoke, аудит безопасности пентестом.

## 6. Что вернуть разработчику

QA-отчёт: что проверено, фактические результаты, найденные дефекты (шаги, ожидаемо/фактически, severity), скриншоты/логи, итоговый вердикт PASS/FAIL. При дефектах — вернуть в разработку и повторить прогон после исправлений.
